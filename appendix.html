HEC MSc DSAIB · CASE 01

Maison Rue

What we built

A small drafting assistant for the shop’s two support colleagues. It reads an enquiry against the provided policies and order snapshot, drafts a reply in the customer’s language and separates supporting facts, missing information and proposed next steps.

Design and value

EDGE: Efficiency. The goal is less time spent finding facts and writing replies, without losing quality. A good reply answers every question, asks for what is missing, sends exceptions to the manager and promises nothing the policies do not allow. We have not measured time saved yet.

5A: Assistant, in a small web app. Flow: enquiry → facts → structured reply → source check → draft for human review. The model handles languages and messages with several questions. Our baseline is a keyword template that answers the first topic it finds, with the same facts.

The customer gives missing details. A support colleague checks damage claims and sends replies. The manager approves exceptions and refunds. The app only proposes these steps: it never sends a message or issues a refund. We kept a single model call rather than several agents, since the case is small.

Team and reproduction

Rémi Barbier: prototype, data setup, tests and documentation (with Codex). Pauline Perrotton: test cases and response validation.

Local version: Python 3 and a logged-in Codex CLI. Run python3 server.py and open http://127.0.0.1:8524. The online version is in vercel/ and uses openai/gpt-4.1 through Vercel AI Gateway. The results below come from the local version.

Tests: python3 -m unittest test_workflow test_server (14 tests) and python3 run_evaluation.py (12 cases). The expected answers are never shown to the model, and source quotes are checked word for word.

Evaluation

M1–M5 come from the brief, V6–V12 are variations we wrote. Both methods get the same messages and facts. An automatic check covers topics, sources and manager routing, then we reviewed the content of each reply with Codex.

The 12 local runs took 114 seconds in total (including CLI startup), against 0.63 ms for the template. Cost and time saved are not measured.

We changed the prompt once after the first run, to stop internal notes from appearing in customer replies. So these 12 cases are a development set, not an unseen test.
